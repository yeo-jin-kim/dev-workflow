# W1 작업 계약: 검증된 브랜치와 병합 결정 자료까지

**개정:** revision 2 — 사용자 승인에 따라 PR 없는 기본 운영으로 변경.
**상태:** 계약 작성 완료. 이번 변경은 문서·평가 정의이며 구현이나 자동 실행을 시작하지 않는다.
**구현 대상:** CoRA와 분리된 dev-workflow. 기계 판독 계약은 [JSON](W1-reviewable-delivery.json),
고정 평가 사례는 [W1-evaluator-v2](evaluations/W1-reviewable-delivery.json)이다.

## 목표와 완료 모습

작업 하나를 시작하면 사전에 정한 범위 안에서 구현 → 검사·브라우저 검증 → 독립 검토 →
필요한 수정·재검증 → 문서 갱신 → commit/push → 브랜치 push 서버 검사 → 병합 결정 자료 준비까지 이어진다.
성공 결과는 **검증된 작업 브랜치와 해당 버전에 대응하는 병합 결정 자료**다. 실제 병합은 사용자 결정으로 남긴다.

PR은 기본적으로 만들지 않는다. 필요한 프로젝트·작업에서 명시적으로 선택할 때만
선택 기능으로 사용할 수 있으며, PR URL·생성 권한·pull_request 이벤트가 없다고
기본 작업을 실패 처리하지 않는다. 브랜치 push 시 필수 서버 검사는 그대로 유지한다.
저장소가 PR 전용 검사를 강제하면 이를 우회하거나 임의로 PR을 만들지 않고 설정 결정을 요청한다.

병합 결정 자료에는 저장소, 소스·대상 브랜치와 정확한 커밋, 변경 요약·비교 링크,
검사·브라우저·독립 검토·서버 검사 결과와 근거, 남은 문제, 제안하는 병합 동작을 담는다.
대상 브랜치가 달라지면 통합 검증을 갱신하고 이전 버전의 승인으로 병합하지 않는다.

현재 실행기는 검사/검토 기반 수정 반복을 이미 제공한다. 이번에는 증거의 소스 버전 연결,
브라우저 실행, 중단 후 복구, 게시와 서버 검사 연결을 구현한다. 미리 있는 기능까지
새로 구현했다고 보고하거나, 사람이 수동으로 단계를 연결한 실행을 자율 실행 성공으로 세지 않는다.

## 작업 범위

| 항목 | 이번에 구현·검증할 내용 |
| --- | --- |
| 검증 기록 | 소스·문서·설정·보호 평가의 지문, 실제 명령/환경/종료 코드/원출력 기록 |
| 브라우저 | 실제 사용할 수 있는 실행 방식 확인, 실제 브라우저에서 대상 프로젝트의 검증 페이지 실행, 결과 자동 수집 |
| 수정 반복 | 테스트 실패와 독립 검토 지적을 전달하고, 수정 후 필요한 검사와 독립 검토 재실행 |
| 복구와 한도 | 단계별 저장, 재시작 시 누적 시간·횟수 유지, 중복 commit·보고서 누락 방지 |
| 게시 | 지정 저장소·전용 브랜치에 검토된 작업 변경만 commit/push하고 검증·병합 결정 보고서 생성·갱신 |
| 서버 검사 | 실제 게시한 버전의 필수 검사를 확인하고 실패하면 같은 수정 과정으로 복귀 |
| 결정 요청 | 이유·근거·선택지·영향·권고안을 하나의 자료로 제공하고 명시적인 답변까지 대기 |

구현자가 자기 완료 기준을 바꿀 수 없고, 읽기 전용 독립 검토와 문서 검토도 생략할 수 없다.
검토 후 문서를 바꾸면 최종 문서 검토가 필요하다. 게시한 소스가 달라졌다면 이전 통과 기록을
그대로 재사용할 수 없다. 변경 영향에 따라 어떤 검사를 재실행하거나 재사용했는지 근거를 남긴다.

브라우저 실행 방식을 아직 구현하지 않았다. 현재 앱의 도구를 CLI가 사용할 수 있다고
가정하지 않으며, 실제로 지원하는 인터페이스와 환경을 먼저 확인한다. 브라우저가 없다면
실행 전 문제를 보고하고, Node 실행이나 화면 캡처를 실제 브라우저 실행으로 표시하지 않는다.

## 사용자에게 맡길 결정

- 개념·핵심 설계 충돌, 완료 기준·평가 정답 변경.
- 새 유료 서비스, 권한·비공개 자료 전달 범위 확대, 정한 예산 확대.
- 제한된 복구 후에도 필요한 환경을 확보하지 못하거나 반복 실패·한도 초과.
- 보고서에 명시한 소스·대상 브랜치와 커밋의 실제 병합·배포.

통상적인 구현 선택, 테스트 환경·CI 설치 누락 수정, 관련 문서 정리, 정해진 범위의 수정·검토,
전용 브랜치 게시와 병합 결정 자료 작성은 매번 허락을 다시 받지 않는다.
과거 병합 승인을 다른 작업 브랜치·버전의 승인으로 사용하지 않는다.

## 중단·게시 정책

권고 기본값은 수정 사이클 3회, 전체 60분이며 구현 시 실제 설정과 누적 한도로 적용해야 한다.
브라우저·검토·서버 검사 대기와 재시작 시간도 포함한다. 현재 실행기의 한도는 호출별이므로
이번 구현에서 보완해야 한다. 금액 사용량 측정 기능은 이번 계약에서 완료를 주장하지 않는다.

실패·판단 대기 상태로 작업을 마쳐도 기존 지시에 따라 안전하게 검토된 작업 변경은 전용 브랜치에
commit/push할 수 있다. 실패한 검사를 숨기지 않고 미완료로 표시한다. 안전한 게시 범위를
확정할 수 없으면 로컬 결과를 보존하고 게시 차단 사유를 알린다. 게시 성공은 작업 통과가 아니다.

## 구현 순서

1. 증거·상태 형식과 브라우저/게시 환경 사전 확인을 만든다.
2. 한도·복구·검토·재검증을 연결하고 고정된 실패 사례로 시험한다.
3. commit/push·병합 결정 자료·push 서버 검사와 중단 후 복구를 연결한다.
4. 작은 실제 CoRA 작업에서 수동 단계 연결 없이 검증된 브랜치와 병합 결정 자료 준비까지 실행한다.

현재 실행기는 자기 저장소를 대상으로 실행하는 것을 거부한다. W1 구현은 별도 dev-workflow
개발 체크아웃에서 유지보수 담당자가 수행하고, 보호 계약·평가는 그 작업 공간 밖에 고정한다.
이 경계를 풀어 구현자가 자기 보호 장치를 바꾸게 하지 않는다. 지금은 실행용 project 설정을
추가하지 않으며, 기존 실행기로 이 계약을 바로 실행할 수 있다고 표시하지 않는다.

## 시험 작업과 완료 조건

실제 시험 작업은 **CoRA의 F1 metadata 불변성 검사를 강화하는 것**으로 제한한다.
현재 검사는 metadata의 node_type을 바꾸므로, 실제 `CognitiveState.state_type`도 바꾸어
점수·경로·종료가 그대로인지 검증한다. 기존 기대값은 유지하고 CoRA 실행 코드는 바꾸지 않는다.
수정 허용 경로는 JSON 계약에 고정했다. 원본 체크아웃은 유지하고 전용 브랜치와 병합 결정 보고서를 쓴다. 기본 시험에서는 PR을 만들지 않는다.

실패 후 자동 수정은 별도의 합성 시험 저장소에서 의도적인 결함으로 입증한다. 실제 CoRA의
완료 기준을 바꾸거나 실패를 조작하지 않는다. 실제 시험에는 기존 F1 브라우저 검증 페이지도
자동 실행해 수동 결과 복사 없이 증거가 모이는지 확인한다.

완료하려면 기존 컨트롤러 검사 15개를 유지하고 [18개 고정 사례](evaluations/W1-reviewable-delivery.json),
실제 시험 실행, 독립 검토와 문서 검토가 모두 통과해야 한다. mock만 통과하거나 사람이
브라우저·게시 단계를 대신하면 부분 구현이다. 실제 결과와 미검증 범위는 구분해 보고한다.

백그라운드 스케줄러, 다음 목표 자동 선정, 자동 병합, CoRA 개념/런타임 변경은 이번 범위에 없다.
