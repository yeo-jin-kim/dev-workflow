# F1 작업 계약 — 거리 감쇠 연상 활성화

**2026-11-05 / revision 2 / 계약 준비 완료, 실행 전**
실행 계약은 [JSON](F1-distance-decay.json), 평가 사례는
[evaluator](evaluations/F1-distance-decay.json)에 있다. 평가 사례는 계약에도
포함되어 구현자·검토자가 같은 내용을 받는다. 의미 라벨은 에이전트가 제안한
합성 사례이며 사용자 확정 실증 정답은 아니다. 첫 시범 실행 전 검토 대상이다.

## 목표와 범위

추상화 수준·노드의 절대 depth에 관계없이 주제와 관련된 경로를 활성화하고,
중심에서 멀어질수록 약해져 종료되도록 한다. 최초 v0의 기본 2-hop 제한을
인지의 정의로 사용하지 않는다. Python, SQLite 기반 자연어 Recall,
브라우저 offline fallback을 함께 확인한다.

영속 weight·원문·Knowledge 승인·근거/owner 경로 정책·자동 병합 정책은 바꾸지
않는다. 기존 작업 중인 변경을 삭제하거나 되돌려 깨끗한 baseline을 만들면 안 된다.

## 첫 구현 후보

- 거리: 중심으로부터 경험적 관계를 몇 번 따라갔는지. 계층 depth/화면 좌표와 별개.
- 경로 점수: `seed × ∏(alpha × 정규화된 관계 강도 × 주제 관련성)`.
- 여러 경로: 최고 점수를 사용하며 반복 경로를 더해 순환 증폭하지 않는다.
- 기준 실험: `alpha=.65`, `epsilon=.05`, 각 factor는 0–1. 실제 0은 그대로 0.
- 길이 d의 경로는 `alpha^d` 이하이므로 0으로 수렴한다. 점수가 epsilon 미만이면
  결과와 전파에서 제외하고, 정확히 같은 경우는 포함한다.
- 관련성: 기존 경험·support·질의 맥락으로 계산하는 로컬 결정적 정책을 설계하고
  근거를 기록한다. 단어 일치나 단순 근접성만으로 결정하지 않는다.

이 수식과 기본값은 실험 후보이며 이론의 확정식은 아니다. 기준을 유지하는
구현 선택과 효율화는 자율적으로 할 수 있다. 주제 관련성은 kernel에 숫자를
주입한 시험만으로 완료할 수 없고 실제 production 계산 경로를 평가해야 한다.

## 고정 평가 사례

| 구분 | 확인할 결과 |
| --- | --- |
| K01 수준·배치 불변성 | depth/추상화 수준/배치만 바꿔도 점수·활성 노드 동일 |
| K02 긴 경로 | 단위 factor 체인에서 .65^d, 2-hop 초과 도달, 7-hop은 .05 미만으로 제외 |
| K03 임계값 | 정확한 경계 포함, 경계 아래 제외 |
| K04 차단 | weight 또는 relevance 0이면 전파하지 않음 |
| K05–06 순환·여러 경로·자원 | 증폭·무한 반복 없음, 최고 경로 선택, seed 포함 state 한도 준수 |
| K07–08 입력·설명 | 잘못된 수치/설정 거부, 종료 이유·truncation·정책/경로 표시, 옛 trace 호환 |
| I01 주제 선택 | agency 질의에서 가까운 로고 문서는 억제, 단어가 겹치지 않는 간접 decision ownership은 활성화 |
| I02 반대 주제 | brand 질의에서 로고 맥락을 decision ownership으로 무분별하게 확산하지 않음 |
| I03 경로 일치 | 실제 실행한 JS와 Python/SQLite의 kernel 결과 비교; 표시/근거 정책은 별도 유지 |
| I04–05 회귀·읽기 전용 | 연상을 관찰된 관계/근거로 오인하지 않고 canonical graph를 바꾸지 않음 |

I01–02의 fixture에는 정상적인 경험 맥락을 기록한다. 답 라벨이나 정답 relevance를
production 코드에 주입하거나 특정 단어를 하드코딩하면 통과로 인정하지 않는다.

## 완료 기준과 산출물

새 전용 테스트 `tests/test_distance_decay_activation.py`, CoRA 전체 테스트,
형식 검사 및 별도 검토가 최종 코드에서 통과해야 한다. 기존 테스트의 기대값을
완화해 통과시키지 않는다. 브라우저 JS를 실제로 실행하지 못하면 parity는 미완료다.

CoRA에 구현·회귀 테스트 및 `docs/implementation/02-F1-distance-decay.md`를 남긴다.
기준/최종 버전, 후보 선택 이유, 사례별 출력, 실행 명령·환경, 수렴 근거,
성능·잘린 결과·남은 한계를 기록한다. 관련 설계·기술 명세·master 상태도 갱신한다.
실행기에서 필수 `documentation_sync` 검토 항목을 추가한다.

## 자율 범위와 결정 요청

자율: 자료구조·queue·관련성/정규화 구현 후보·국소 최적화·관련 테스트/문서 수정,
고정 기준 안에서의 제한된 재시도. 변경 후보와 실패 기록은 남긴다.

사용자 결정 필요: 개념/성공 기준/평가 라벨 변경, 근거 정책 변경, 새 모델·외부
서비스·비공개 데이터 의존, 중요한 품질/비용 절충. 실행 환경 부족이나 예산 소진은
기술적 중단 사유로 보고하며 성공으로 처리하지 않는다.

권장 실행 한도는 3회/30분이다. 이는 계약 설명만으로 적용되지 않으므로 실제
실행 시 CLI 옵션에 명시한다. 금액 예산 계측은 없다. 이 한도에서 parity/전체
검증이 끝나지 않으면 미완료로 남긴다.

## 실행 전 준비

이번 작업은 계약 구체화뿐이다. 현재 프로젝트 설정은 원래 CoRA checkout을
가리키고 있으므로 바로 개발을 시작하지 않는다. 계약 검토 후 기존 미커밋 변경을
보존한 독립 작업 공간, 기준 버전·digest, Python/JS 실행 환경을 준비해야 한다.
worker는 실행 중 commit/push하지 않는다. 이후 사용자 지시에 따라 parent는 작업 결과마다 검증 상태를 명시해 commit/push한다. 미완료 구현은 별도 실험 브랜치로 보존하며 merge/deploy/예약 실행은 허용하지 않는다.
